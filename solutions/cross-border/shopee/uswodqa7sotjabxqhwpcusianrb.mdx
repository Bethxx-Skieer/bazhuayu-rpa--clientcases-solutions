## 一、用户与需求

核心矛盾：老板每天早上问数据、手工汇总费时；罚款/毛利/绩效看不到；多站点口径不统一（按站点+合计+环比）。

两类客户痛点同源，数据来源不同：

- 未购 SaaS 客户（新卖家/小团队）：人工从各后台导数据、手工贴表格汇总，全靠手；
- 已购 SaaS 客户（店小秘 ERP 等）：店小秘管订单库存，经营日报汇总层（罚款/毛利/绩效）不覆盖，仍要人手工汇总。

适用客户：多站点（店群）卖家。本场景为「汇总层」：数据源 = 各采集场景底表（订单/GMV/广告花费/退款/罚分）+ 官方数据报表（访客/转化/销售表现）。

## 三、解决方案

### 3.1 功能概述

为虾皮卖家团队打造的经营日报方案（老板驾驶舱，多店铺汇总），汇总各采集场景底表，生成「一页纸」经营日报。

每天定时触发并调度多个工具，调起八爪鱼 RPA（Agent 的工具底座，能耦合多系统、完成自动化任务执行）每日汇总各采集场景数据（订单/GMV/广告花费/退款/罚分）+ 官方数据报表（访客/转化/销售表现）生成日数据底表，智能体按老板视角生成「昨日经营日报」：GMV/订单数/广告 ROI/退款率/毛利估算（按站点+合计+环比）。每天 定时执行，晨间推送老板。

### 3.2 系统结合

| 要素 | 说明 |
|-|-|
| 客户现有工具盘点 | **未购 SaaS 客户**：无第三方工具，日报全靠手工汇总。    
**已购 SaaS 客户**（主流组合）：店小秘 ERP（管订单库存，汇总层不覆盖） |
| 数据/能力来源 | **无 SaaS**：各采集场景底表（订单/GMV/广告/退款/罚分，RPA 归集）+ 官方数据报表（访客/转化/销售表现，登录采集）。    
**有 SaaS**：店小秘订单/库存数据 + 各场景底表（汇总口径联动） |
| RPA 耦合动作 | 作为 Agent 的工具底座，每天 08:30 汇总各场景底表（各底表口径校验、缺数标注），统一流转给智能体；任一数据源失败自动重试、缺数告警 |
| 耦合出的新价值 | 单工具给不了的端到端结论：各场景底表一次取齐 → 站点+合计双层归集 → 环比计算 → 异常标注（GMV 骤降/广告超标/退款激增）→ 一页纸晨报，**晨间自动推送老板** |

### 3.4 为何这么设计

要同时回答三个问题：**为什么不能只用 SaaS/API？为什么不能纯靠智能体写代码？为什么 RPA 是执行底座？** 本场景的核心是"每日汇总、站点归集、环比异常、挂了有人管"。

#### 1）逐项对比

| 对比维度 | SaaS/API 堆叠（店小秘） | 纯智能体（智能体写代码） | 智能体+自动化工具（RPA 工具底座） |
|-|-|-|-|
| 实现方式 | 店小秘管订单，汇总层不覆盖 | 能抓数据能算，但全要自己接 | 各场景底表汇总 + 站点归集 |
| 每日定时 | 不覆盖 | 智能体无法常驻轮询 | RPA 每天 08:30 定时执行 |
| 汇总口径 | 无 | 需自建汇总逻辑 | 归集规则可视化配置 |
| 使用成本（总拥有成本） | 店小秘订阅费（主体另算） | 代理 IP + 服务器 + 开发维护人力，隐性成本高 | 一份平台订阅跑多流程，单方案边际成本 ≈ 0 |
| 维护人要求 | 低（工具现成） | 规则调整都要开发介入 | 可视化流程，运营自己可调指标 |

#### 2）优劣势说明

|  | SaaS/API 堆叠（店小秘） | 纯智能体（智能体写代码） | 智能体+自动化工具（RPA 工具底座） |
|-|-|-|-|
| 优势 | 订单/库存数据权威 | 无订阅费；    
可深度定制日报模型 | 底表汇总+站点归集；    
环比异常即开即用；    
非技术人员可维护 |
| 劣势 | 汇总层不覆盖 | 归集与计算全自建；    
AI 生成代码是生成性的 | 本地电脑运行需保持开机；    
订阅费；    
依赖各采集场景数据就绪 |

#### 3）结论

| 论点 | 说明 |
|-|-|
| 汇总层定位 | 本场景是「汇总层」：数据源 = 各采集场景底表 + 官方数据报表，依赖各场景数据就绪后价值最大化 |
| 异常阈值实锤 | GMV 环比降幅 >20% 或广告占比 >30% 或退款率 >10% 触发标注（实锤） |
| 分阶段实施 | 一期先搭官方数据报表拉取基础版，二期各采集场景就绪后升级完整版 |
| 一个底座跑多流程 | 客户购买 RPA 平台是跑多个流程（日报/对账/罚款），本方案只是其中一个——平台订阅费被多流程摊薄 |
| 时间 | 老板要的是"晨间一页纸"，不是"等运营手工汇总" |
